LINQ GroupJoin — Poster Cheat Sheet

Um “left join com agrupamento”: 1 linha por outer + um grupo com 0..N matches do inner. Inclui dicas escondidas: chave composta, ordem/nomes, null, comparadores e receitas de query.
Query syntax + Method syntax
GroupJoin ≠ Join

Imprimível (A4)

Modelo mental (sem dor)

GroupJoin retorna 1 resultado por item do lado esquerdo, sempre. O lado direito vira um grupo (IEnumerable<TInner>) — pode estar vazio.
Join
“Achata” (inner join):
1 linha por combinação
GroupJoin
“Agrupa” (left + group):
1 linha por outer + grupo
LEFT JOIN achatado
GroupJoin + SelectMany(DefaultIfEmpty)

Receita: LEFT JOIN (achatado)

Padrão clássico para manter todos do outer, mesmo sem matches no inner. 

var q =
  from c in customers
  join o in orders on c.Id equals o.CustomerId into og
  from o in og.DefaultIfEmpty()
  select new
  {
    c.Name,
    OrderId = (int?)o?.Id
  };
  • Pegadinha: o DefaultIfEmpty() vem depois do into, no segundo from.
  • Sem match ⇒ o vira null (por isso o o?.Id).

GroupJoin “puro”

Quando você quer trabalhar com o grupo (contagens, últimos, agregações).

var q =
  from c in customers
  join o in orders on c.Id equals o.CustomerId into og
  select new
  {
    c.Name,
    Orders = og,
    Count = og.Count(),
    Last = og.OrderByDescending(x => x.Date)
             .FirstOrDefault()
  };
  • og é um IEnumerable. Em LINQ to Objects, enumerar várias vezes custa.

Chave composta: “AND” implícito

Em join você não escreve a==b && c==d. O “AND” é projetar uma chave composta. 

// ✅ OK (nomes e ordem batem)
from c in customers
join o in orders
on new { c.Id, c.Region }
equals new { Id = o.CustomerId, o.Region } into og
  • Ordem importa: new { c.Region, c.Id } não “casa” com new { o.CustomerId, o.Region }.
  • Nomes importam: se você renomear, renomeie dos dois lados.

Pegadinhas silenciosas

  • Comparer padrão: usa EqualityComparer<TKey>.Default.
  • null: pode quebrar expectativa (em SQL, NULL = NULL não é “true” no sentido clássico).
  • EF vs Objects: nem tudo traduz (ex.: comparer custom).

Normalização de null (quando fizer sentido):

// Ex.: tratar null como string vazia
on (c.Region ?? "") equals (o.Region ?? "")

Comparador customizado (Objects)

Útil para case-insensitive, cultura etc. (geralmente não traduz no EF).

var q = customers.GroupJoin(
  orders,
  c => c.Email,
  o => o.Email,
  (c, og) => new { c, og },
  StringComparer.OrdinalIgnoreCase);
Dica: Se você estiver no EF/SQL, prefira normalizar (ex.: ToUpper()) com cuidado e verifique a tradução/índices.

Performance: múltiplas enumerações

Em LINQ to Objects, isso enumera o grupo várias vezes:

select new {
  Count = og.Count(),
  Sum   = og.Sum(x => x.Total),
  First = og.FirstOrDefault()
};

Objects: materialize uma vez (quando fizer sentido):

var q =
  from c in customers
  join o in orders on c.Id equals o.CustomerId into og
  let list = og.ToList()
  select new {
    c.Name,
    Count = list.Count,
    Sum   = list.Sum(x => x.Total)
  };
EF/SQL: cuidado com ToList() no meio (pode quebrar tradução ou puxar dados demais). Prefira agregações traduzíveis no select (Count/Sum/Any/Max...).

Query vs Method (equivalência)

Mesma ideia, sintaxes diferentes.

// Query syntax
from a in A
join b in B on a.Id equals b.AId into bg
select new { a, bg }

// Method syntax
A.GroupJoin(
  B,
  a => a.Id,
  b => b.AId,
  (a, bg) => new { a, bg });

Receitas (copy/paste)

Outer sem matches

var q =
  from c in customers
  join o in orders
    on c.Id equals o.CustomerId into og
  where !og.Any()
  select c;

Último item do grupo

var q =
  from c in customers
  join o in orders
    on c.Id equals o.CustomerId into og
  let last = og.OrderByDescending(x => x.Date)
               .FirstOrDefault()
  select new { c.Name, last };

Agregações por outer

var q =
  from c in customers
  join o in orders
    on c.Id equals o.CustomerId into og
  select new {
    c.Id,
    Count = og.Count(),
    Total = og.Sum(x => x.Total),
    HasAny = og.Any()
  };
Checklist rápido: (1) outerKey == innerKey? (tipo/ordem/nomes) · (2) precisa manter outer sem match? use into + DefaultIfEmpty · (3) cuidado com null · (4) em Objects, evite enumerar o grupo 10x · (5) em EF, garanta que traduz.
